# 30FPS 입술 분석 정책

2026-11-08 구현. 브랜치 `fix/lip-30fps-summary-20261108`, 기반 main `f286477`.
운영 활성화·새 GPT 생성 검증은 이 문서 작성 시점에 수행하지 않았다.

## 변경

정책 `PHONE_ROLE_SPARSE_30FPS_V1`은 실제 MFA 구간에 들어온 프레임 PTS만 사용한다.
30FPS에서 0.1초보다 짧은 음소에 일괄적으로 3프레임을 요구하던 조건을 분리했다.
프레임 복제·보간·인접 음소의 프레임 차용·시간 구간 확장은 하지 않는다.

| 측정 | 새 최소 관측 | 추가 조건 |
|---|---|---|
| 모음의 입술 벌림 | 1프레임 | 같은 음소·초중종성의 실제 참조 필요 |
| 원순 모음의 정규화 입술 폭 | 1프레임 | 2차원 형상 비교이며 3차원 돌출 측정이 아님 |
| 양순음의 최소 벌림(폐쇄 정도의 대리값) | 2프레임 | 해당 구간 전체가 관측되어야 함; 완전한 닫힘 동작의 보증이 아님 |
| 입술 동작의 상대 시점 | 3프레임 | 실제 변화량 기준 충족, 같은 단어 참조 필요 |
| 기존 DTW·보정 점수 | 기존 조건 유지 | 1~2프레임을 궤적·전문가 보정 점수로 승격하지 않음 |

일부 프레임에 얼굴이 없더라도 실제로 보이는 프레임의 정적 형상은 사용할 수 있다.
이때 `PARTIAL_VISIBILITY_STATIC_ONLY`를 남기고 폐쇄·타이밍은 채점하지 않는다.
모든 프레임이 보이지 않거나 구간에 프레임이 없으면 점수는 계속 null이다.
참조 없음, 자기 영상과의 비교, 동기화 미확인, 모호한 정렬도 임의 점수로 바꾸지 않는다.

정적 비교식·임시 척도·60:40 종합점수 규칙은 변경하지 않았다. 적용 가능한 관측과
참조의 성분만 비교한다. 비교 범위가 기존 60% 기준 미만이면 부분 입술 점수를 별도로
제공하고 종합점수는 음성 점수를 유지한다. 일부 음소의 점수를 전체의 정확도로 표시하지 않는다.
현재 참조 영상 한 문장에는 없는 음소도 있으며, 이 변경은 인구 통계 기준을 새로 만든 것이 아니다.

## 참조와 기존 결과

- 기존 `EXACT_WORD_COVERAGE_V1`, `PHONE_ROLE_PARTIAL_PROVISIONAL_V1`의 재현 조건은 유지한다.
- 새 참조 capture v2·catalog v4는 1프레임 정적 참조도 허용한다. 기존 capture v1·catalog v2/v3는 기존 조건을 유지한다.
- `prepare_lip_reference.py capture --allow-sparse-frames`로 새 capture를 만든다.
  compile에는 실제 검토와 `--lip-score-policy`가 필요하다. 사용자 지정 참조는 별도의 명시적 지정 컴파일러를 사용한다.
- 참조 capture는 구간 전체가 보이는 경우만 후보로 등록한다. 짧은 참조로 DTW calibration을 만들 수 없다.
- Seungun CORE bytes·기존 결과·spool·기존 H5 자산은 수정하지 않는다.

## 피드백

같은 시도의 측정·참조 점수가 있는 입술 대상부터 최대 두 개를 선택한다.
점수는 없어도 실제 형상이 관측됐다면 `OBSERVE_VISIBLE_SHAPE_ONLY`로 자기 관찰 연습을
선택할 수 있다. 참조가 없는 상태에서 교정 방향을 만들거나 참조 비교를 요구하지 않는다.
관측 자체가 없고 촬영의 가림·얼굴 누락이 확인되면 `CAPTURE_VISIBILITY_ONLY`로 촬영 안내를 한다.
이 대상들도 기존 음성 대상과 합쳐 최대 세 줄·5문장·300자 제한에 포함한다.

원본 CORE와 보조 측정을 분리한 **단일 GPT 요청**을 유지한다. 모델은
`gpt-6-luna`, `reasoning_effort=none`, Standard(`service_tier=default`) 그대로다.
프롬프트에는 구체적 좋은 예문 대신 범위별 허용 행동과 금지 추론을 명시했다.
참고: [OpenAI 공식 프롬프트 가이드](https://developers.openai.com/api/docs/guides/prompt-engineering).

## 고정 H5 연결

소스의 선택기만 바꾸면 운영의 고정 H5에는 반영되지 않으므로
`deploy/dlpc/build_sparse_lip_h5.py`도 추가했다. 이전 Luna H5를 부모로 검증하고
`bridge/visual.py`와 기본 시스템 프롬프트만 교체한다. CORE, 참조, 서버 채점표,
추가 채점 지침, 요청 설정은 보존한다. direct/internal 신규 identity·스키마 분기·실행 등록도 포함한다.
새 배포 시 두 lane의 `canonical_sparse_lip_<lane>_20261108_v1_h5`를 함께 선택해야 한다.
기존 H5 경로를 계속 선택하면 새 피드백 선택기가 실행되지 않는다.
