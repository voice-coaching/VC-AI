# 근거 기반 코칭: 실제 두 영상 QA

2026-09-19 KST. 사용자 요청에 따른 격리 실행이다. 운영 API·DB·서비스·모델 가중치·검출 threshold는 변경하지 않았다. 이전 AGENTS의 QA 보류보다 이번 명시적 실제 QA 요청을 우선했다.

## 검증 범위

기존에 전송을 승인한 두 영상을 해시 대조한 뒤 CPU Seungun 추론, VAD 측정, 실제 음소별 dense window/입술 추출, 새 코칭 프롬프트의 GPT 생성 및 계약 검증을 수행했다. 모델은 `gpt-6-astra`, low reasoning이다. CLOVA 재호출, 사용자 API 접수·콜백·DB 저장·프론트 E2E는 이번 범위에 포함하지 않았다.

개인 영상·원시 좌표·분석 원문·생성 원문·인증정보는 commit에 넣지 않았다. 원본은 보존하고 실행 자료는 권한이 제한된 별도 QA 폴더에 남겼다.

## 실제 발견과 수정

- 다중 후보 입력에서 GPT가 대치처럼 보이는 한 후보만 반환했다. validator는 모든 입력 후보를 요구해 `coaching_candidate_coverage`로 거절했다. 프롬프트에 서버가 선택한 모든 후보를 정확히 한 번씩 포함하도록 명시했다. 같은 실제 근거의 재호출에서 3개/1개 후보가 각각 누락 없이 검증됐다.
- fallback 로그에는 로컬 validator의 허용된 reason code만 추가했다. 공급자 응답 본문과 비밀값은 기록하지 않는다.
- 항목이 있으면 항상 같던 결과 요약에 연습 항목 수와 판단 보류 범위를 표시한다. 후보 수를 정확도·오류 개수·향상 점수로 해석하지 않는다.
- 40점 요약은 정수 ms 시각으로 구간을 골라, 실제 966.667ms 프레임이 966ms에 끝나는 구간에 잘못 포함될 수 있었다. decode receipt의 원래 microsecond 시각을 사용하도록 수정했다. 구간을 넓히거나 모델 threshold를 바꾸지 않는다.

초기 QA 묶음의 Windows CRLF와 실제 worker LF 사이 해시 차이, 일시적인 진단 래퍼의 static method 바인딩 오류는 **테스트 준비 문제**였다. 운영 장애로 판정하지 않았다. 실제 배포 worker와 줄바꿈 정규화 후 바이트가 같은 것을 확인하고 래퍼를 바로잡아 재실행했다.

## 발음 품질 판정의 범위

최종 실행은 실제 40점 영상 분석과 정확한 프레임 시각 필터를 적용한 근거를 GPT에 전달했다. 두 결과 모두 JSON Schema와 후보 ID/포함 범위를 통과했고 `generation.source=LLM`, `fallbackReason=null`이었다. 영상 1은 후보 0·3·5의 3개 항목, 영상 2는 후보 5의 1개 항목을 반환했다. GPT 호출 소요시간은 각각 **18.437초 / 7.131초**다. 이 값은 1회씩의 GPT 생성·검증 시간이며 전체 서비스 지연이나 p50/p95가 아니다.

최종 prompt SHA-256: `5098a378cc63b78506d1a6fa8dbbbb55e1f07af20de10aef1e1d56963e1f6e07`. QA 기준 소스는 `89be7429795c7477090c963d7fd313b28caab19e`와 이번 수정이며 운영 배포 리비전이 아니다.

두 영상 모두 30개 기대 위치를 읽었다. 판단 보류는 각각 6개/18개, 적격 후보 묶음은 5개/1개였다. 실제 생성 입력은 최대 3개/1개다. 두 영상의 모호한 같은 `ㅇ deletion`은 REVIEW_ONLY이며 새 주된 교정 대상으로 쓰이지 않았다.

새 피드백은 목표 소리가 유지된 모델 후보와 `ㅋ→ㄱ` 후보를 구별하고, 목표 발음 연습·단어 연결·자기 확인을 제공했다. 개인 혀 위치·기류 오류·입 벌림 정답을 관찰했다고 단정하지 않았다. 이 검토는 실제 생성물과 입력 근거 사이의 적합성 검사다. 전문가의 독립 청취 정답, 모델 정확도·학습 효과 검증은 아니다. 적격 후보가 적은 두 번째 영상을 더 잘 발음했다고 판정하면 안 된다.

## 영상 참조 검증

기존 release의 세 파일 해시와 로더 연결은 통과했다. 그러나 교정 기준의 타당성은 **미통과**다.

- 40개 음소에 공통 벌림 규칙 하나를 적용한다.
- 보정·평가 사례 수가 각각 2개이며 release에 검증 가능한 화자 분리 manifest가 없다.
- 배포된 옛 생성 코드는 실제 평가 결과 대신 `violation_count=0`을 상수로 기록한다. 첫 구현에서 이 생성기를 폐기했지만 기존 운영 artifact를 교체한 것은 아니다.
- sync 수치는 두 영상에서 각각 -160ms / +60ms로 계산됐다. 기존 정책 통과와 실제 시간 정답 검증은 구별한다. 별도 동기화 정답은 없다.

따라서 `referenceStatus=NOT_VALIDATED`, `correctiveClaimsAllowed=false`를 유지한다. 새로운 정상 참조값이나 통과 receipt를 만들지 않는다. 20ms CTC 구간과 약 33ms 영상 프레임 간격 때문에 해당 구간에 유효 프레임이 없거나 하나뿐일 수 있다. 주변 dense decode 성공을 해당 음소의 충분한 연속 궤적으로 표현하지 않는다.

실제 추출 결과:

| 영상 / 후보 위치 | 주변 프레임의 40점 추출 | 매핑된 20ms 구간 안의 정확한 프레임 수 |
| --- | --- | ---: |
| 영상 1 / 0 | 6/6 프레임, 각각 40점 | 0 |
| 영상 1 / 3 | 6/6 프레임, 각각 40점 | 0 |
| 영상 1 / 5 | 6/6 프레임, 각각 40점 | 0 |
| 영상 2 / 5 | 7/7 프레임, 각각 40점 | 1 |

영상 2의 666.667ms 프레임은 662–682ms 구간에 포함된다. 여기서 입 너비·내외부 벌림·면적·입꼬리 비대칭의 정적 비율 6개가 생성됐다. 추가 변화율 1개는 앞 문맥 프레임과의 차이를 사용하므로 음소 구간 안의 연속 궤적 검증은 아니다. 영상 1의 기존 4점 벌림 관측은 주변 구간의 가까운 프레임을 사용하며, 해당 20ms 구간 안의 정확한 시각 표본이라고 해석하지 않는다. 관측 구간 수가 다르므로 이 비율만으로 두 영상 전체의 입 벌림 크기를 비교하지 않는다.

실제 40점 worker는 운영 파일과 바이트 해시가 같았고, 마지막 추출 경로의 예외는 없었다. 직렬 CPU QA에서 영상 단계는 각각 59.369초 / 22.963초였다. 전체 희소 검출의 후보별 반복 실행이 포함된 값이며, 운영 동시성·GPU·캐시를 갖춘 지연 측정은 아니다.

## 속도·쉼과 재녹음 비교

`backend_analysis.speech_timing`은 **명시적 오프라인 QA 전용**이며 운영 worker·콜백·공개 DTO에는 연결하지 않았다. 선택적 의존성 `webrtcvad==2.0.10`은 격리 QA 디렉터리에만 설치했다.

[WebRTC VAD Python 문서](https://github.com/wiseman/py-webrtcvad)에 맞춰 16kHz mono PCM16, 20ms frame을 사용한다. 기준은 mode 1, 내부 비음성 구간 200ms 이상이다. 같은 입력을 mode 0–3으로 측정해 민감도를 함께 기록했다. 모델의 검출 threshold나 배포 설정은 변경하지 않았다.

| 관측 | 영상 1 | 영상 2 |
| --- | ---: | ---: |
| 실제 PCM 길이 | 4,842.6875ms | 2,709.3125ms |
| 첫~마지막 VAD 발화 범위, mode 1 | 3,800ms | 2,560ms |
| VAD 발화로 분류한 시간 합, mode 1 | 3,320ms | 2,400ms |
| 대본 13음절 / VAD 발화 범위 | 3.4211/초 | 5.0781/초 |
| 같은 지표, mode 0–3 범위 | 3.4211–4.3624/초 | 5.0781–8.2278/초 |
| 200ms 이상 내부 비음성, mode 1 | 1개, 480ms | 0개 |
| 200ms 이상 내부 비음성, mode 2/3 | 0개 | 0개 |

VAD mode 0/1이 영상 1 시작의 60–200ms를 발화로 잡으면서 200–680ms를 내부 쉼으로 분류했다. mode 2/3은 이 초기 구간을 발화로 잡지 않는다. 따라서 **480ms를 실제 문장 중간 쉼이라고 확정하지 않는다.** 실제 무음과 언어적 쉼, CTC 시간과 발음 지속시간을 구분한다.

분자는 대본 음절 수이며 실제 발화 전사를 검증한 값이 아니다. 이 지표는 같은 대본에 대해 두 번째 영상의 감지된 발화 범위가 더 짧다는 뜻이다. 네 mode에서 방향은 같지만 정확한 사용자 발화 속도·정상/과속 판정은 제공하지 않는다.

사용자는 같은 사람·장비·장소임을 확인했다. 실제 촬영 순서와 독립 전사는 미확인이라 `testvideo1 → testvideo2`는 비교 방향일 뿐 학습 후 향상 순서가 아니다. 비교기는 같은 문장·측정 버전·VAD 설정을 요구하고 같은 PCM 재사용을 새 녹음으로 취급하지 않는다. 변화량은 제공하되 `improvementJudgment=null`을 유지한다. 원래 코칭 API의 `comparison=null`은 그대로다.

## 남은 배포 조건

최종 점검은 실제 오디오의 VAD 재측정 일치, 마지막 불완전 프레임의 무음 처리 방지, 동일 PCM 비교 거절, 문장·정책·VAD 설정 불일치 거절, 정확한 프레임 시각 경계, 실제 LLM 후보 포함 범위, 미검증 참조의 교정 비활성 유지를 통과했다. 변경 Python 3개 구문, 관련 문서 상대 링크, diff 공백 검사도 통과했다. 일반 회귀 전체 실행과 운영 E2E 결과는 아니다.

실제 두 표본의 호출·관측·출력 확인은 수행했다. 이를 화자 독립 발음 정확도, 정상 영상 참조, 적절한 쉼·속도, 학습 효과의 통과 기록으로 대체할 수 없다. 해당 정답 자료를 확보해 독립 평가한 뒤 공개 측정 계약·재녹음 조회·UI를 연결해야 한다. 현재 Draft PR의 운영 활성화를 이 QA만으로 승인하지 않는다.
