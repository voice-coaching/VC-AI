# Clova 상세 피드백 수정과 분석 보완 계획

> Clova 시기의 변경·연구 계획을 보존한 문서다. 운영 Clova는 폐기됐고 현재는 GPT-6(`gpt-6-astra`) 코칭을 사용한다. [2026-09-28 실제 배포 파이프라인](runpod_deployed_pipeline_20260928.md)에 현재 근거 선택·전문가 예시·fallback·점수 상태를 기록했다. 아래 생성 제한과 기동 절차는 현재 운영값이 아니다.

2026-09-09. 기존 A6000 INT8의 짧은 답변이 반복된 원인을 코드와 이전 실행 결과에서 확인했다. 이번 변경은 **이미 존재하는 관찰·연습 내용을 최종 설명까지 보존**한다. 새로운 조음 오류 판정 모델이나 입술 교정 기준을 만들었다는 뜻은 아니다.

외부 원본·파생 자료의 영구 저장소는 Backblaze B2로 지정한다. `.env` 설정,
자료별 수집 순서, B2 객체 구조와 RunPod 임시 캐시는
[Backblaze 수집·활용 계획](backblaze_external_data_plan_20260909.md)을 따른다.

## 후속 검토: 다양한 교정을 위한 외부 근거 확보

같은 날 사용자의 지적을 반영해 공식 자료와 원논문을 검색했다. **기존 보완 계획은 계측과 설명 보존에 치우쳐 있었고, 다양한 교정 방법의 지식 기반을 확보하는 작업이 부족했다.** 입술 수치나 문장 길이를 늘리는 것만으로 교정의 종류가 늘어나지는 않는다. 아래 계획을 기존 계측 보완과 병행하는 우선 작업으로 추가한다. 이 절은 조사와 설계이며 아직 런타임에 구현·배포한 변경은 아니다.

### 이미 있는 데이터와 실제로 없는 정보

저장소의 [한국어 오류·안내 ontology](../configs/coaching/korean_error_advice_ontology_v1.json)는 AI Hub 71490 기반 오류 구간 176,523건의 집계와 초성·종성·모음·경음화·비음화·격음화·유음화 등의 분류를 이미 기록한다. 외부 데이터가 전혀 없는 상태가 아니다. 다만 이 파일도 특정 음소와 오류 태그의 결합 근거, 전문가 검토와 production 승격을 미완료로 표시한다. 기존 안내 초안 역시 대체로 참조음을 듣고 다시 읽는 수준이다. 이 집계 건수는 이번에 원자료를 다시 조사한 수치가 아니다.

필요한 자료는 세 종류다. **오류 탐지를 학습할 음성·영상**, **목표 발음을 어떻게 가르칠지 설명하는 교육 지식**, **실제 학습자의 오류에 어떤 교정 행동이 도움이 됐는지 보여주는 사례**다. 세 자료는 서로 대체되지 않는다.

### 목표 발음 안내와 개인 오류 진단을 구분

현재 제한을 ‘혀·입술에 관한 설명은 모두 금지’로 해석하면 교육 자료가 있어도 안내가 빈약해진다. 다음 두 가지를 분리해야 한다.

- **목표 발음 안내:** 현재 목표 음소와 문맥에 맞는 공식 교육 자료를 근거로 발음 방법과 대조 연습을 알려 준다. 사용자의 실제 조음 상태를 측정했다는 주장은 하지 않는다. 예를 들어 ‘ㅗ/ㅓ’의 입 모양 차이를 설명하는 연습은 위 교원용 지침서를 바탕으로 구성할 수 있다.
- **개인 오류에 따른 교정:** ‘이번에는 입술이 충분히 닫히지 않았다’, ‘다음 모음으로 전환이 늦었다’처럼 현재 시도의 잘못을 특정한다. 이 안내에는 해당 음소·문맥의 검증된 음성/영상 측정과 진단 근거가 필요하다.

전자는 교육 지식을 확보하면 먼저 확장할 수 있다. 후자의 교정 기준이 완성될 때까지 모든 목표음 설명을 보류할 필요는 없다. 다만 ‘목표음을 내는 방법’에 대한 지식을 ‘사용자의 혀 위치를 보았다’는 진단으로 바꾸면 안 된다.

### 수정한 실행 순서

1. **교육 지식 카탈로그를 먼저 만든다.** 목표 음소·단어/음절 위치·앞뒤 음운 문맥별로 `발음 방법 → 대조 연습 → 단어/문장 연습 → 스스로 비교할 항목`을 구성한다. 각 항목에 출처 URL·쪽수·버전, 적용 조건, 관측 가능한 modality, 확인할 수 없는 사실과 검토 상태를 기록한다. 특정 문맥의 받침이나 연음에 초성의 발음 지시를 그대로 적용하지 않는다. 기존 ontology를 확장하되 미승인 초안을 운영 승인으로 바꾸지 않는다.
2. **Clova 앞에 근거 선택 단계를 둔다.** 같은 시도의 음성·영상 분석과 목표 발음 문맥을 기준으로 해당 교육 항목만 선택한다. 일반 발음 안내와 현재 시도에 대한 진단을 서로 다른 종류의 claim으로 전달한다. 매 요청마다 임의 웹 검색을 붙이기보다는 검토된 자료를 로컬에서 검색하도록 설계한다. 현재 `requiredFragments`는 선택된 내용의 누락 방지에 재사용하고, 적용 문맥 및 근거 없는 개인 진단의 혼입도 검증 대상으로 추가한다.
3. **오류 유형 분석을 교육 지식과 연결한다.** 71490의 기존 태그·실제 발음·시간 경계를 검토하고, 모음 혼동 방향, 자음 대립, 받침·음운규칙의 적용 여부 등 구분 가능한 유형을 결정한다. 정답 오류태그는 학습·평가 라벨로만 사용한다. 실행 시에는 새 음성에서 추론한 결과와 검증된 신뢰도를 사용해야 한다.
4. **입술은 움직임 근거가 있는 행동부터 확장한다.** 538/68의 관찰과 SNU-MAC 같은 조음 자료를 활용해 폐쇄/개방 전이, 원순성에 관련된 모양, 다음 소리로의 전환을 연구한다. 이들은 추가할 **후보**이며 현재 승인된 진단이 아니다. 음성과 결합해 허용 변이와 오류를 구별한 뒤 개인별 교정으로 연결한다. 모든 음소를 같은 벌림 수치에 맞추지 않는다.
5. **공개 자료에 없는 교정 사례를 수집한다.** `교정 전 발화 + 전문가의 오류 판단 + 권한을 확보한 교육 지시 + 교정 후 재발화 + 변화/유용성 판단`을 같은 문맥으로 묶는다. 이것이 어떤 행동을 선택할지 개선하는 자료다. 원어민 모양과 다르다는 이유만으로 잘못된 발음이라고 라벨링하지 않는다. 교사에게 연락하거나 자료를 수집하는 단계는 아직 실행하지 않았다.

이 실행 순서는 외부 자료의 내용과 현재 코드의 단절을 함께 고려한 **프로젝트 설계 제안**이다. 외부 데이터만으로 위 기능이 이미 구현·검증됐다고 해석하지 않는다. 자료별 실제 사용 조건을 기록하고, 특히 SNU-MAC의 상업·학습 권한과 교육 콘텐츠의 서비스 재사용 범위를 확인한 뒤 반영한다. 이번 조사에서는 음성·영상 데이터셋 다운로드, 모델 학습, RunPod 재배포, QA를 수행하지 않았다.

## 이번 수정

음성 입력을 위치, 단어 연습, 문장 재녹음, 분석 한계의 네 claim으로 확장했다. 선택 음소를 원문 단어·음절에 연결하고, 관측된 CTC 정렬 시각이 있으면 대략적인 다시 듣기 위치를 제공한다. 삭제 구간에 보간으로 붙인 시각은 실측 위치처럼 설명하지 않는다.

연습은 `단어 전체를 소리를 끊지 않고 천천히 → 같은 단어를 원래 속도로 → 문장 전체를 다시 녹음 → 처음 녹음과 번갈아 같은 단어의 연결 부분 비교`로 바꿨다. 예를 들어 ‘끗’에 연결된 분석 표지 ‘ㅅ’을 따로 떼어 발음하라고 안내하지 않는다. CTC의 대치·삭제 후보는 실제 대치·생략이 확정됐다는 진단과 구분한다. LLM 실패 때에도 첫 문장만 반환하지 않고 네 claim 전체를 보존한다.

입술 입력에는 기존 승인 행동과 연결된 영상 시간 범위, 실제 벌림 비율, 재촬영 비교를 넣었다. 40점 옵션이 활성화된 경우 평균 바깥 벌림·안쪽 벌림·입꼬리 높이 차이, 입 너비를 기준으로 정규화했다는 뜻과 관찰 한계를 최종 메시지에 반드시 보존한다. 단순히 베타 주의 문장만 출력하면 거부된다.

면적 두 종류, 영상 좌표상의 입 너비와 가능한 변화율도 승인 입력에는 유지한다. 사용자 메시지에서는 위의 세 형상 수치를 우선하며, 나머지 수치의 전부 나열을 강제하지 않는다. 면적 비율의 분모는 입 너비의 **제곱**이다. 현재 변화율은 직전 문맥 프레임과의 차이를 포함할 수 있어 입술이 닫힌 시점·방향·실제 개폐 속도를 뜻하지 않는다.

입력 계약을 `voice_coach.grounded_advice_input.v4`로 올리고 claim마다 `requiredFragments`를 추가했다. 각 필수 구절은 승인 원문에 실제 존재해야 하고, LLM 메시지에 그대로 남아야 한다. ID만 선택하고 본문을 생략하면 상세 승인 원문으로 폴백한다. 기존 v3 입력은 읽을 때 v4로 변환하지만, 이전 입력에 없는 관찰을 자동으로 생성하지 않는다. 출력 JSON 계약은 v3를 유지한다.

프롬프트는 관찰 → 단어 연습 → 문장 비교 → 입술 관찰과 한계를 충분히 설명하도록 변경했다. 보통 4~8문장을 권하고 최대 1,000자를 허용한다. HyperClova adapter는 `candidateDisclosure=omit`도 코드로 확인한다. 필수 구절 검증은 **상세 누락 방지**이며, 그 뒤에 추가되는 모든 문장이 근거에 부합하는지를 판정하는 완전한 의미 검증기는 아니다. 새 진단을 완전히 자동 차단한다고 주장하지 않는다.

| 실행 설정 | 이전 | 이번 |
|---|---:|---:|
| 출력 토큰 상한 | 256 | 512 |
| 서버 생성 제한 | 75초 | 150초 |
| Clova 클라이언트 기본 제한 | 90초 | 180초 |
| 일반 음성 CLI의 별도 기본 제한 | 30초 | 공통 180초 |
| 입력 토큰 상한 | 4,096 | 4,096 |

모델·revision·A6000·INT8 threshold 6.0·CPU offload 설정은 유지한다. 응답이 길어지면 지연과 요청당 GPU 사용 시간이 늘어난다. 위 값은 상한이며 예상 응답 시간이 아니다. 이전 짧은 답변의 약 33초 측정값을 상세 응답에 재사용하지 않는다. 동시 요청 503, 종료 토큰 없는 응답 거부, 반복 경고 억제는 유지한다.

## 분석 결과 자체의 부족과 보완 순서

### 1. 위치와 측정 출처부터 보강

현재 Seungun production은 [production_pipeline.py](../seungun/src/korean_phone_ctc/production_pipeline.py)의 검출 점수 순으로 음소 하나를 고른다. CTC의 확률·후보·entropy·span은 오류 원인을 직접 설명하지 않는다. 특히 nonblank spike의 길이를 실제 발음 지속시간이나 말속도로 사용하면 안 된다. 관측 정렬과 보간 구간을 구분하는 timing provenance, 단어·음절 interval, 정렬 신뢰도와 음질 요약을 버전이 있는 분석 계약에 추가한다. 이후에야 ‘어느 부분을 얼마나 길게/짧게’ 같은 설명을 검토할 수 있다.

현재 [production 시각 sidecar](../src/voice_coach/pronunciation_attempts/adapters/production_visual_sidecar.py)는 음소 중앙에 가장 가까운 **한 프레임**을 사용하며, 이 프레임이 음소 구간 밖에 있을 수도 있다. 공개 cue에는 실제 선택 시각과 표본 수가 없다. 실제 프레임 시각, 관찰 표본 수, 구간 내부/문맥 표본 구분, coverage를 추가하고 표본이 부족한 경우 시간적 교정 판단을 내리지 않도록 한다. 이전 영상의 약 20ms 음소 범위는 입술 움직임 전체를 설명하기에 짧다.

### 2. 입술 형상에서 움직임 분석으로 확장

40점의 현재 공개 값은 주로 구간 평균과 최대 변화량이다. [P6 trajectory](../src/voice_coach/visual_feedback/services/p6_lip_trajectory.py)의 시간 정보를 시작·중간·끝 형상, 개방/폐쇄 전이 방향과 시점, 음성 경계와의 시차로 요약하는 계약이 필요하다. 최소 관찰 프레임과 정렬 품질을 통과한 값만 쓴다. 정면 2D 측정으로 실제 돌출 깊이·혀·성문·기류를 판정하지 않는다.

### 3. 오류 유형과 교정 행동의 근거 마련

음성은 검출 점수와 CTC 후보만으로 혀 위치나 오류 원인을 붙이지 않는다. 원문/실제 기대 발음의 문맥을 반영한 전문가 라벨, 검증된 정렬과 음향 특징을 바탕으로 구체적인 오류 유형을 분리하고, 검토된 연습 지시를 카탈로그로 만든다. 기존 설계의 MFA·Parselmouth·운율 경로는 현재 production wrapper에 연결돼 있지 않으므로 구현 존재와 실제 호출을 구분한다.

입술은 현재 두 영상 기반 공통 벌림 기준을 이상적인 발음 정답으로 사용할 수 없다. 음소·문맥별 참조와 화자/촬영 조건이 분리된 관찰 자료, 사람이 판단한 발음 및 교정 행동의 적절성이 필요하다. 이를 근거로 폐쇄 정도, 벌림의 시점, 너비/둥근 모양 등 관찰 가능한 후보를 검토하고, 유효한 행동만 policy·catalog·renderer·release에 함께 추가한다. geometry mapping artifact만으로 새 행동을 승인하지 않는다.

### 4. 운율과 개인별 재시도 연결

검증된 단어·음절 정렬 이후 속도·쉼·F0·강도 경로를 연결한다. 같은 원고·발화 조건의 참조와 음질 기준이 먼저 필요하다. 음소 교정과 운율 안내가 서로 충돌하지 않게 우선순위를 정하고, 이전 시도와의 차이를 같은 기준으로 비교할 수 있을 때 개인별 변화 설명을 추가한다. Clova에는 원시 음성·영상 대신 근거·단위·범위·한계·승인 행동을 담은 요약만 전달한다.

### 5. 설명의 품질과 운영 비용

전문가가 승인할 수 있는 오류 설명/연습 지시와 관찰 요약의 대응을 확정한 뒤 생성 문장의 의미 보존도 검토한다. 숫자를 늘리는 것만으로 피드백 품질이 개선됐다고 판단하지 않는다. 상세 생성의 실제 지연과 사용성은 개발자 검증 대상으로 남긴다. 학습·평가용 원본과 과거 분석은 B2에, 승인된 작은 기준·모델과 실행에 필요한 자산은 RunPod에 유지해 기존 비용 절감 방향을 따른다.

## 적용 범위와 상태

40점 관찰은 기존 `--closed-beta-lip-geometry-artifact` 옵션 또는 backend의 대응 설정이 있을 때만 들어온다. 옵션이 없는 경로에 40점 분석이 자동으로 생기는 것은 아니다. 이번 변경은 미검증 관찰을 정답 정책으로 승격하거나 새 교정 행동을 승인하지 않는다.

수정 코드는 로컬과 RunPod `odqpp9eqly0v0x`의 영구 overlay·실행 사본에 반영했다. 17개 overlay 파일의 크기와 SHA-256 일치를 확인했다. 정상 시작 스크립트로 재기동한 프로세스는 PID 12252이며 `/health`가 `ready`, 정책 `grounded-detail-v1-20260909`, 입력 v4, 출력 512토큰, 생성 제한 150초를 반환했다. 새 프로세스의 `last_completion`은 null로, 기동 확인 중 추론을 하지 않았다.

Python AST 구문 검사와 `git diff --check`를 수행했다. 브라우저·자동 회귀 테스트와 영상/LLM 재추론은 이번 요청에서 실행하지 않았다. 이전 4건 통과 기록은 이전 피드백 정책의 결과이며 새 정책의 품질 검증으로 간주하지 않는다. 기존 단일 claim·v3 직접 생성 fixture와 잘못된 입 너비 단위 fixture는 새 계약과 달라 개발자의 후속 QA에서 갱신이 필요하다. 테스트 파일은 변경하지 않았다. Git commit/push는 하지 않았다.

RunPod의 `deployment/detail-feedback-20260909/`에 반영 기록과 health를 보관하고, 이전 overlay는 `overlay-before-detail.tar.gz`로 보존한다. 후속 B2 복구 객체는 기존 비공개 버킷의 `intelligentai/recovery/deployment-int8-20260909-odqpp9eqly0v0x/deployment-int8-detailed-feedback.tar.gz`다. 완료된 전송·해시 값은 [이전 실행 기록](runpod_b2_storage_migration_execution.md)에 남긴다.
