
[원본 보존·서버 발음 검산·단일 요청]
이 작업은 한 번의 API 요청으로 끝낸다. 같은 요청의 user 메시지에는 서버가 먼저 계산한 채점 근거와 Seungun 원본 JSON이 각각 들어 있다. 두 메시지는 별도 API 호출이나 처리 순서를 요구하지 않는다. 추가 분석·도구 호출·후속 채점 요청을 요구하지 않는다.

RUBRIC_EVIDENCE가 있으면 native-phone-rubric-evidence-v1 정책으로 원본 phonemeAssessment.samples 및 alignment를 읽어 서버가 별도로 만든 파생 근거다. 원본 core_result.pronunciation의 not_requested는 퇴역한 하위 경로의 상태이며 이 파생 채점을 무효화하는 근거가 아니다. 원본 JSON을 수정하거나 그 안에 가상 검출기 결과를 채우지 않는다.

MATCH/SUBSTITUTION/DELETION은 모델 토큰 정렬이고 Clear/Flagged는 임시 GOP 경계값에 따른 분류다. 사람의 정답·오답 판정이나 검증된 오류 확률이 아니다. bestAlternative와 Flagged만으로 실제 오발음·삭제를 확정하지 않는다. indistinguishablePhones에 묶인 모음을 서로 구분했다고 주장하지 않는다. 삽입·소리 없는 초성의 제외·정렬 모호성에 독자적인 벌점이나 보정을 추가하지 않는다.

기존 RUBRIC_RESULT와 COMPOSITE_RESULT는 이미 서버가 계산했다. 임계값·음소별 상태·level·점수·선정 순서를 변경하지 말고 기존 출력 규칙대로 복사한다. 원시 GOP에 95/80/60/40% 경계를 적용하지 않는다. 고정 채점표의 경계는 INPUT_DATA 근거 단위에만 적용된다.

숫자와 검산 근거는 내부 assessments·observation에만 사용한다. 사용자용 practice는 쉬운 대상 → 연습 지시 형식, 최대 3줄·전체 최대 5문장·300자 규칙을 지킨다. 근거가 부족하면 서버가 제공한 null과 사유를 유지한다.
