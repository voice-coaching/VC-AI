intelligentAI 저장소 작업을 시작한다.

## 1. 먼저 읽을 것

1. `.codex/ai_rule_developer/GLOBAL_RULES.md`
2. 현재 요청에 해당하는 작업 유형별 규칙
3. 관련 코드, tests, config/schema
4. 루트 `docs/`의 현재 프로젝트 명세
5. 자료가 있으면 `.codex/ref_docs`의 사용자 관리 참고자료

충돌 우선순위는 현재 사용자 요청 > GLOBAL_RULES > 작업 유형별 규칙 > 루트
`docs/` > `.codex/ref_docs` > 기타 기록이다. 실제 구현 상태는 코드·테스트·config와
실행 결과로 확인하며, 문서와 충돌하면 추측하지 말고 충돌을 보고한다.

## 2. 작업 시작 확인

- `git status --short --branch`로 기존 변경을 확인하고 사용자 변경을 보존한다.
- 요청을 조사/설계/구현/실행/검증/문서화 중 하나 이상으로 분류한다.
- 요청 범위와 성공 조건, 보호 데이터·외부 실행·장시간 GPU 작업 여부를 식별한다.
- 사용자가 지정한 파일, CLI, 표본이 있으면 그것부터 사용한다.

## 3. 프로젝트 핵심 경계

- 저장소: `intelligentAI`; Python package: `voice_coach`; Python 3.12; FastAPI.
- 현재 루트 서비스는 무상태이며 DB가 없다.
- 구조는 `src/voice_coach`의 domain/application/service/port/adapter와 연구 모듈을
  따른다. `app/features`나 MySQL CRUD 템플릿을 새로 강제하지 않는다.
- API/CLI/GUI에는 비즈니스 판단, 모델 호출, 파일 처리, 학습 로직을 넣지 않는다.
- Seungun이 오디오 발음 판정과 selected phone을 소유한다. visual feedback과 LLM은
  승인된 같은-attempt 근거를 보충·표현할 뿐 새 진단을 만들지 않는다.
- 근거·권리·동의·gate가 부족하면 fail-closed 한다.
- 데이터/ML 작업은 감사 -> 작은 smoke -> 평가 순서로 진행하고 human/locked/
  promotion gate를 우회하지 않는다.
- `.env.local`, 제한 음성·영상/label, row-level 심사 자료, model weight/checkpoint,
  token과 개인 식별자를 출력하거나 Git에 넣지 않는다.

## 4. 행동 범위

- 조사·리뷰·진단 요청은 읽기와 비파괴 검증만 한다.
- 수정·구현 요청은 필요한 로컬 변경과 관련 검증까지 수행한다.
- 외부 쓰기, 대규모 다운로드, 전체 학습, locked 평가, 데이터 삭제, commit/push는
  명시적 요청 없이 수행하지 않는다.
- 범위 밖 리팩토링, 문서 복원, 기능 추가, 임의 status/digest 생성은 하지 않는다.

## 5. 완료와 응답

- 가장 관련 있는 테스트/계약 검사/smoke를 실행하고 command와 결과를 확인한다.
- `implemented`, `running`, `verified`, `failed`, `blocked`, `contract-only`,
  `historical`을 구분한다.
- 검증하지 못한 항목은 이유와 남은 위험을 적는다.
- 응답은 작업 유형 -> 적용 규칙 -> 결과 -> 검증 -> 미확인 항목 순으로 작성한다.
- 파일 변경은 경로별로 설명한다.

현재 repository checker는 `.codex`와 `docs/architecture`를 retired local location으로
거부한다. 사용자의 현재 요청이 이 로컬 문서 편집을 허용하더라도 checker를 몰래
약화하거나 이 파일들을 일반 제품 commit에 포함하지 않는다.
