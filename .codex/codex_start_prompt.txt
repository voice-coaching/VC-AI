지금부터 `intelligentAI` 저장소의 작업을 시작한다.

이 저장소는 제한된 한국어 L2 음성 데이터를 이용해 발음 진단, 근거 제한 코칭,
기준 음성, 재녹음 비교를 단계적으로 검증하는 연구 프로젝트다. 계획·정적 준비·
실제 실행·사람 평가 완료를 서로 바꾸어 말하지 말고, 미해결 gate를 우회하지 않는다.

## 시작 순서

1. 먼저 `.codex/ai_rule_developer/`의 모든 규칙과
   `.codex/ref_docs/PROJECT_CONTEXT_AND_GOVERNANCE_KO.md`를 읽는다.
2. 작업과 직접 관련된 현행 정본을 소유권별로 읽는다. 오디오 경로는
   `seungun/README.md`와 `seungun/docs/`, visual sidecar는
   `docs/architecture/`, API는 `docs/api/`, 현행 평가 경계는
   `docs/evaluation/`, 데이터 저장·반출은 `data/README.md`, 논문 주장과
   미해결 갭은 `docs/paper/`를 우선한다. 현재 tracked tree에는 저장소 전체를
   대표하는 단일 completion tracker·구현 계획·privacy/license matrix·실행 편차
   ledger가 없으므로, 삭제된 `docs/constraints/` 경로를 정본으로 추측하거나
   부재한 gate를 통과로 처리하지 않는다.
3. `.codex/ref_docs`의 다른 자료가 있으면 사용자 제공 참고자료로 읽되, 프로젝트
   상태·계약의 정본은 루트 `docs/`임을 유지한다.
4. 현재 요청을 다음 중 하나 이상으로 분류한다: 아키텍처, 도메인/스키마, API,
   서비스 로직, route/UI 경계, 외부 연동, 데이터 준비, 학습/평가, 실험 운영,
   리팩터링, 문서화.
5. 해당 규칙과 정본 문서의 gate를 적용한 뒤 가장 작은 범위로 구현·검증·문서화를
   수행한다.

## 우선순위

문서가 충돌하면 다음 순서로 판단한다.

1. 사용자의 현재 요청
2. `.codex/ai_rule_developer/GLOBAL_RULES.md`
3. 요청 유형별 `.codex/ai_rule_developer` 규칙
4. 루트 `docs/`의 관련 정본 계약·상태 문서
5. `.codex/ref_docs`의 참고자료
6. 기타 보조 문서

## 항상 지킬 원칙

- Python 계층을 분리한다. API/CLI/UI는 입력 검증과 변환만 하고 business logic은
  application/service에, filesystem/network/GPU/subprocess는 adapter에 둔다.
- entity, request/response DTO, schema, domain model, view model과 expected label,
  realized label, feature, prediction, evidence를 혼용하지 않는다.
- 새 기능·API·모델 주장·자동 교정은 현재 요청과 확인된 계약에 없는 한 추가하지
  않는다. Oracle은 실제 모델 또는 production capability의 대체물이 아니다.
- AI Hub 원본·파생 음성·전사·상세 annotation·raw identifier·원천 경로·제한
  manifest·checkpoint·`.env.local`·token을 Git, 공개 문서, 공개 응답에 넣지 않는다.
- label, QC, privacy, split, immutable hash, 선행 gate, 권한·라이선스·동의를
  검증하지 못하면 fail-closed로 멈추고 관찰 사실을 보고한다. heuristic label
  repair, split 누수, stale/partial run의 성공 처리, 수동 registry 수정은 금지한다.
- 외부 시스템은 전용 typed client/adapter 뒤에서만 사용한다. 인증은 사용자 제어
  세션을 열어 처리하며 secret을 출력·입력·교체하지 않는다.
- 코드가 계약·데이터·gate·privacy/license·외부 연동·API·상태·구조를 바꾸면 같은
  작업에서 관련 루트 `docs/`도 실제 동작에 맞게 갱신한다.

## 응답 방식

응답의 첫 부분에 다음을 짧게 적는다.

1. 판단한 작업 유형
2. 우선 적용한 `.codex` 규칙과 루트 `docs/` 정본 문서
3. 실제 구현·검증 결과와 미확인 또는 실패한 항목

파일을 변경했으면 파일 경로별로 변경 내용을 구분한다. 실제 실행하지 않은 모델,
metric, API, 사람 평가, commit/push를 완료했다고 말하지 않는다.
